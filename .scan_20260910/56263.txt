### 🐛 Describe the bug

For a model output that contains text before AND after a tool call, the two delivery modes disagree: streaming returns the post-tool text, non-streaming drops it. The tool parser is inconsistent with its own streaming mode.

Reproduction (CPU only, no GPU or model weights; tokenizer download only):

```python
from vllm.entrypoints.openai.chat_completion.protocol import ChatCompletionRequest
from vllm.tool_parsers.deepseekv3_tool_parser import DeepSeekV3ToolParser
from vllm.tokenizers import get_tokenizer

MODEL_OUTPUT = ("let me check the weather.<｜tool▁calls▁begin｜>"
    "<｜tool▁call▁begin｜>function<｜tool▁sep｜>get_weather\n```json\n"
    '{"city": "Paris"}\n```<｜tool▁call▁end｜><｜tool▁calls▁end｜>It is 30 degrees.')
tok = get_tokenizer("deepseek-ai/DeepSeek-R1")
p = DeepSeekV3ToolParser(tok)
req = ChatCompletionRequest(model="m", messages=[])

# non-streaming parse
print("full  :", repr(p.extract_tool_calls(MODEL_OUTPUT, req).content))

# streaming parse, token by token
ids = tok.encode(MODEL_OUTPUT, add_special_tokens=False)
out, prev_text, prev_ids = [], "", []
for i, tid in enumerate(ids):
    text = prev_text + tok.decode([tid])
    d = p.extract_tool_calls_streaming(
        prev_text, text, tok.decode([tid]),
        prev_ids, ids[:i + 1], [tid], req)
    if d and d.content:
        out.append(d.content)
    prev_text, prev_ids = text, ids[:i + 1]
print("stream:", repr("".join(out)))
```

Observed:

```
full  : 'let me check the weather.'
stream: 'let me check the weather.It is 30 degrees.'
```

The trailing "It is 30 degrees." is dropped by the non-streaming parse and kept by the streaming parse. Downstream, `messages_full_converter` (`/v1/messages` non-streaming) then never sees that text, while `message_stream_converter` emits it as a text block after the tool_use block - for the same generation, /v1/messages streaming shows the trailing text and non-streaming loses it.

### Root cause

Non-streaming `extract_tool_calls` implementations truncate content at the tool-call start token and never resume afterwards:

- deepseekv3_tool_parser.py: content = text before `<｜tool▁calls▁begin｜>`
- hermes_tool_parser.py:109: `content = model_output[: model_output.find(self.tool_call_start_token)]`

Streaming implementations emit post-tool text as content deltas (deepseekv3_tool_parser.py:248, `DeltaMessage(tool_calls=[], content=text)`).

### Expected behavior

Both delivery modes return the same content for the same generation.

### Proposed fix

Make the DeepSeek-V3 parser's non-streaming parse include the post-tool text, matching its own streaming mode. The same truncation exists in hermes_tool_parser.py and can follow separately if maintainers agree it is also unintended. OpenAI clients currently lose this text in non-streaming mode, so returning it is a correction, not a new feature.
