## Bug: compressed-tensors quantization config collapses GDN (gated-delta-net) linear attention token distinctness — Qwen4Exp/qwen3.8-class hybrid models produce garbage under ANY CT config, identical weights run clean under fp8 config

### Environment
- vLLM: `0.28.0+strix` (kyuz0 TheRock gfx1151 build, but the implicated code paths — compressed-tensors model wrap + GDN/FLA attention — are architecture-generic)
- Model: Qwen3.8-Flash-Next (`Qwen4ExpForConditionalGeneration`), 48 decoder layers, hybrid GDN linear attention + QSA full attention + MoE (512 experts) + PLE n-gram embedding
- Hardware: AMD Radeon 8060S (gfx1151), ROCm; reproduced single-GPU TP=1 (should be HW-independent since the failure is representational, not numerical-precision)

### Summary

Converting an fp8 checkpoint to a compressed-tensors W4A16 checkpoint (int4-g64/g32 symmetric, group scales, standard `weight_packed`/`weight_scale` layout — byte-verified against llmcompressor reference models) makes generation collapse to repetition soup. **The same model files, loader, and code produce correct output when served with the original fp8 quantization_config.** Through a nine-stage elimination (details below), every quantization-related component was proven byte- and math-exact; the failure is that **GDN linear-attention layers collapse hidden-state token distinctness whenever a compressed-tensors config is present on the model — even when the CT group targets only `RoutedExperts` and every GDN Linear resolves to `UnquantizedLinearMethod`.**

### Reproduction

1. Serve a hybrid GDN+MoE checkpoint with any `quantization_config: {"quant_method": "compressed-tensors", ...}` (group targeting only routed experts; GDN/attention/embeddings all in `ignore`).
2. Send any chat completion. Output is multilingual repetition soup.
3. Re-serve the identical weights with the original fp8 quantization_config → correct output.
4. Zero out routed experts entirely (monkeypatch `TritonWNA16Experts.apply` to write zeros) under the CT config → output becomes clean EOS (no soup), **but hidden states still collapse**, proving the routed-expert path is not the cause.

### Key evidence (hidden-state sweep)

Per-layer self-cosine of decoder-layer input hidden states (78-token real prefill):

| config | L0 entry | L1 entry | L2 entry | L47 |
|---|---|---|---|---|
| fp8 config (works) | 0.05 | ~0.05–0.1 | healthy | healthy |
| CT config (soup) | 0.05 | 0.40 | 0.55, norm 5.5e8 | 0.43, norm 2.3e10 |
| CT config + experts zeroed | 0.49 | 0.62 | 0.66 | 0.77 |

Layer-0's GDN `linear_attn` output has self-cosine 0.78 on distinct-token input (0.05 at entry) under CT config, with sane magnitudes (norm 52). Warmup batches (identical dummy tokens) pass; real prefill collapses. This direction-collapse with sane norms is the signature of attention reading/writing the same state slot or ignoring token distinctness.

### What we verified as NOT the cause

1. **Checkpoint bytes**: engine-resident expert tensors byte-exact vs safetensors (layer-consistent comparison; self-decode rel_err 0.119 = int4 quantization noise floor, and full expert path vs fp8-dequant reference rel_err 0.165 end-to-end through both GEMMs + SiLU).
2. **Upstream Triton W4A16 MoE kernel**: replaced entirely with a vectorized decode+einsum implementation matching fp8 ground truth offline — output still soup; the replacement's output was captured in-engine and matches its offline computation (rel 0.005).
3. **Loader/stack layout**: live WNA16 stacks match expected `[E, K/8, 2N]` layout including scales, verified by full-tensor dump.
4. **Router**: gate weights loaded, topk_weights 0.07–0.23 summing to 1.0, no NaN.
5. **PLE custom op**: runs live (ids up to 3.1e8), returns sane embeddings (norm 26.9).
6. **Compile mode**: soup under both `--enforce-eager` and `--compilation-config '{"cudagraph_mode":"NONE"}'`.
7. **CT group targeting**: `targets: ["Linear"]` vs `targets: ["RoutedExperts"]` — identical soup.

### Hypothesis

The presence of a compressed-tensors config changes how the GDN/FLA attention path executes (candidate: the CT model-level wrap/transform hooking `CompressedTensorsLinearMethod` dispatch on GDN's `in_proj_qkv`/`out_proj`/`in_proj_a/b/z`, or a metadata/state-layout change on the hybrid mamba-state machinery when the model is constructed under `CompressedTensorsConfig`), such that per-token queries/keys/states are no longer distinct. Because warmup (single dummy sequence) passes, any per-request metadata (cu_seqlens/query_start_loc/state-slot addressing) that differs between warmup and real chunked prefill is implicated.

### Impact

All hybrid GDN/Mamba-linear-attention MoE models (qwen3-next-class, qwen4exp-class) are unusable with compressed-tensors checkpoints on this build — including correct, llmcompresser-reference-layout W4A16 quantizations. This blocks the primary memory-reduction path (weights 64.5→38 GiB/GPU, KV capacity 2x) for 128 GB Strix Halo deployments.
