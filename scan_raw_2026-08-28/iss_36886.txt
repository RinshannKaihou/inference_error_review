## Describe the bug

**TL;DR** — `--dcp-size 8` on GLM-5.3-Flash (DSA), commit `033446bb05f`:

1. **Crash**: the DSA index-K cache is sized per-rank (`index_buf_size = size`) but written/read with the allocator's DCP-virtual locs (no `%dcp` / `//dcp` anywhere on that path, unlike the main c-KV kernel). Once cumulative allocation crosses `max_total_num_tokens`, writes go out of bounds and corrupt neighboring buffers — random victim kernel crashes (6 distinct signatures observed), deterministic trigger point. Fix: size index-K to the virtual loc space, same treatment #33348 gave the draft pool. Validated diff below.
2. **Quality**: with the crash fixed, DCP still degrades outputs — chain-of-thought inflates 4–9×, details garble. Removing only `--dcp-size 8 --dcp-comm-backend ag_rs` restores quality.

Quality comparison — same node / weights / args, the only change is removing `--dcp-size 8 --dcp-comm-backend ag_rs`; `/v1/chat/completions`, temperature 0, `max_tokens` 2000; "reasoning" = character length of `reasoning_content`:

<details>
<summary>Defect 1 details: root cause and evidence</summary>

Under DCP the paged allocator hands out virtual locs in `[0, max_total_num_tokens * dcp_size)` (`PagedTokenToKVPoolAllocator(size * dcp, page * dcp)`, `kv_cache_configurator.py`). The main c-KV write localizes in-kernel (`set_mla_kv_buffer_kernel`: `loc % DCP_WORLD_SIZE == DCP_RANK` + `loc // DCP_WORLD_SIZE`, `sglang/kernels/ops/kvcache/mla_buffer.py`). The DSA index-K cache does not:

- write: `Indexer._store_index_k_cache` uses raw `forward_batch.out_cache_loc` (fused and fallback paths), no rank filter, no division;
- read: top-k reads via metadata page tables that also carry untranslated virtual locs;
- but `DSATokenToKVPool.index_buf_size` defaults to the per-rank `size` (`memory_pool.py`).

Write and read agree in virtual space (every rank stores every token — replication, which top-k over the full sequence needs), so everything works until cumulative allocation first crosses `max_total_num_tokens`. From then on index-K writes (132 B/token/DSA-layer) land past the buffer and corrupt whatever the caching allocator placed next. Victim differs run to run — ATen `index_put` device assert, `causal_conv1d` illegal read, DeepGEMM fault, `chunk_gla` fault, VocabParallelEmbedding id assert — while the trigger is deterministic (±1 prefill chunk; 642,752 @ `--mem-fraction-static 0.75`, 493,120 @ 0.71).

Before the fix: 3 concurrent 300K-token `/generate` requests crash 5/5 exactly at the crossing. After: repeated 3×300K waves run clean.

Triage note for the quality defect: GLM-5.3-Flash `layer_types` places `linear_attention` (KDA, mamba state, no paged KV) at layers 0–2; DSA layers are `[3, 7, 11, ..., 43]`. Per-layer tensor diffs covering only the first three layers cannot see a paged-KV/metadata divergence.
</details>
