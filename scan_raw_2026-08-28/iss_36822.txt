### Describe the bug

GPTQ Marlin MoE has two correctness issues when serving BF16 models with tensor parallelism.

First, `w13_scales` and `w2_scales` are always allocated as `torch.float16` instead of following `params_dtype`. For BF16 models, this causes the hidden states and scales to use different dtypes, triggering an assertion in the Marlin MoE kernel:

```text
AssertionError: moe_wna16_marlin_gemm assumes hidden_states.dtype
(torch.bfloat16) == w1_scale.dtype (torch.float16)
```

Second, the `w2_scales` shape and loading behavior are incorrect when tensor parallelism and act-order (`desc_act=True`) are enabled. Each TP rank requires the full `w2` scale table in this case, but the current logic allocates or loads a TP-sharded version. This can introduce invalid scales and propagate NaNs to the output logits, causing errors such as:

```text
Assertion `probability tensor contains either inf, nan or element < 0` failed.
```

or:

```text
NaN detected! sampler: next_token_logits
```

## Expected behavior

- Scale tensors should use `params_dtype`.
- With `desc_act=True`, each TP rank should load the full `w2` scale table.
- Without act-order, each TP rank should load only its local `w2` scale partition.

## Proposed fix

The fix is proposed in [PR #35955](https://github.com/sgl-project/sglang/pull/35955).
