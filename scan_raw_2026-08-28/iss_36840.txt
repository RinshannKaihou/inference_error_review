TBO unreachable for GLM-5.3-Flash (DSA+mamba hybrid): silent --enable-dp-attention reset + missing Glm5NextDecoderLayer strategy
## Environment

- sglang: `0.0.0.dev1+g033446bb05` (dev build from image 1.0.0.270), editable install at `/sgl-workspace`
- Hardware: single node, 4x H20 (SM90), NVLink; `--tp-size 4`
- Model: GLM-5.3-Flash (HF, arch `Glm5NextForConditionalGeneration`) — hybrid DSA + mamba + FP8 MoE (289 experts)
- Other flags: `--context-length 16384 --mem-fraction-static 0.95 --max-running-requests 40 --moe-runner-backend triton`

## Problem

`--enable-two-batch-overlap` cannot be enabled for this model, and the first failure mode is actively misleading.

### 1. Misleading error: `--enable-dp-attention` is silently reset

```
--enable-two-batch-overlap
```
→
```
ValueError: When enabling two batch overlap without an EP a2a backend (moe_a2a_backend='none'),
--enable-dp-attention is required (DeepSeek-V4 non-EP DP TBO path).
```

Adding the flag it asks for changes nothing:

```
--enable-two-batch-overlap --enable-dp-attention
```
→ the **identical** ValueError.

Cause: `_data_parallelism_defaults` post-process in `arg_groups/overrides.py` resets `enable_dp_attention=False` (and `enable_dp_lm_head=False`) whenever `dp_size == 1`, with no warning:

```python
@register_post_process
def _data_parallelism_defaults(view: Any) -> dict:
    if view.dp_size == 1 and view.ep_join_mode != "scale":
        return {"enable_dp_attention": False, "enable_dp_lm_head": False}
    return {}
```

So `_check_two_batch_overlap()` then tells the user to add exactly the flag that was passed and silently dropped. Suggest either warning on the silent reset, or an error that names `--dp-size` when TBO is requested with `dp_size == 1`.

### 2. With `--dp-size 4`, capture crashes: `filter_batch` rejects mamba fields

With `--tp-size 4 --dp-size 4 --enable-dp-attention --enable-two-batch-overlap`, validation passes and the model loads, but decode CUDA graph capture dies on all ranks:

```
Exception: 2 errors happen:
Field mamba_track_indices has value, but is not yet supported ...
Field mamba_track_mask has value, but is not yet supported ...
```

`TboForwardBatchPreparer.filter_batch` gates on a hand-enumerated field list, and GLM-5.3-Flash is a DSA + mamba hybrid whose `ForwardBatch` always carries `mamba_track_indices` / `mamba_track_mask`. TBO is therefore unreachable for this model.

Locally we added the mamba fields to the per-seq slice list in `filter_batch` (slicing by `start_seq_index:end_seq_index`, same as `seq_lens`). The gate then passes, but capture hits the next blocker:

### 3. No TBO operations strategy for `Glm5NextDecoderLayer`

```
File ".../batch_overlap/operations_strategy.py", line 77, in init_new_tbo
    raise NotImplementedError
```

`OperationsStrategy.init_new_tbo` dispatches only on `DeepseekV2DecoderLayer`, `Qwen3MoeDecoderLayer`, `MiMoV2DecoderLayer`, `DeepseekV4DecoderLayer`; `Glm5NextDecoderLayer` (plain `nn.Module`, no op_* decomposition) has no strategy. Full TBO support for this hybrid layer (DSA attention + mamba + FP8 MoE) would require an operations decomposition, not a small patch.

## Request

1. Fix the silent reset / misleading error interaction so TBO failure tells users they need `--dp-size` (or warn when `enable_dp_attention` is dropped).
2. Consider TBO support for `Glm5NextForConditionalGeneration` (DSA + mamba hybrid): `filter_batch` mamba-field handling and an operations strategy for `Glm5NextDecoderLayer`.

Related: #36829 (EAGLE3/MTP draft for the same model is also blocked).
