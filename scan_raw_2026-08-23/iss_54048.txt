#### ISSUE #54048 [Bounty $2500] ttnn.remainder: wrong results (off by whole multiples of the divisor) for |dividend/divisor| ratios beyond ~2^23, on both Wormhole and Blackhole
## Summary

`ttnn.remainder`'s scalar/unary fp32 path computes the quotient via a float
multiply-by-reciprocal, corrects it by at most `1`, and stops. Once the true quotient's
magnitude exceeds roughly `2^23` (~8.4 million) — i.e. the dividend is more than
~8.4 million times the divisor — floating-point rounding in that multiply can leave the
quotient estimate off by more than the single correction can fix, and the kernel returns
a result that is wrong by a whole integer multiple of the divisor:

```
ttnn.remainder(x=1.42606e7, 3.0)   ->  1.0   (kernel)
correct value                      ->  2.0
```
```
ttnn.remainder(x=5.70425e7, 3.0)   ->  -1.0  (kernel)
correct value                      ->  2.0
```

This is confirmed identical on **both Wormhole and Blackhole** (`ckernel_sfpu_remainder.h`
is byte-for-byte the same algorithm on both architectures — the two files differ only in
cosmetic `sfpi::` qualification, not logic).
