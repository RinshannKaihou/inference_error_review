#### PR #53474 [KV Offload] Size node-local shared regions by local_world_size
STATE:open merged:no
## Summary

`SharedOffloadRegion` is backed by a node-local `/dev/shm` mmap. In a multi-node TP deployment, the current CPU/Tiering offload specs size each non-replicated mmap row by global `world_size` and fold worker slots by global `world_size`.

For a 2-node TP8 worker, each node only has 4 local ranks writing to its local mmap. Sizing/folding by 8 leaves half of each node-local row unused and cuts the effective CPU offload block count in half.

This PR threads `ParallelConfig.local_world_size` into native offloading config and uses it for:

- CPU offload non-replicated row sizing.
- CPU offload shared-region rank/slot selection.
- Tiering offload shared-region rank/slot selection.

Single-node and legacy configs keep the existing fallback to `world_size`.
