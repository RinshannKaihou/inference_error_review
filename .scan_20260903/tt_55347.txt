### 55347 [closed] ttnn.rms_norm on a rank-0 tensor computes x / |x|: epsilon is dropped, x = 0 gives NaN and every |x| < sqrt(eps) gives ±1
**Component / Area:** ttnn normalization, `rms_norm` host dispatch (rank-0 branch)

**Issue Type:** Bad Outputs

## Summary

`rms_norm` has an explicit rank-0 path
([rmsnorm.cpp#L43-L58](https://github.com/tenstorrent/tt-metal/blob/9fa00fce13cda1538f0130695576408ff5b05665/ttnn/cpp/ttnn/operations/normalization/rmsnorm/rmsnorm.cpp#L43-L58)):

```cpp
// For 0D tensors
if (rank == 0) [[unlikely]] {
    auto result = ttnn::divide(input_tensor, ttnn::abs(input_tensor, output_memory_config), ...);   // x / |x|
    if (weight) ... multiply;  if (bias) ... add;
    return result;
}
```

`epsilon` is never read on this branch; it is only forwarded to `prim::layer_norm` for rank >= 1. The registered golden
([normalization.py#L113-L125](https://github.com/tenstorrent/tt-metal/blob/9fa00fce13cda1538f0130695576408ff5b05665/ttnn/ttnn/operations/normalization.py#L113-L125))
is `x * rsqrt(mean(x^2) + eps)`, which for a scalar is `x / sqrt(x^2 + eps)`, and `torch.nn.functional.rms_norm` agrees. So the
op returns `0 / 0 = NaN` at `x = 0` and exactly `±1` for every `|x|` below about `sqrt(eps)`, where the reference is a value
between 0 and 1.

This is a source-level analysis with a host replay; I do not have a card. The composition is two elementwise ops, so the
device result is what the replay shows up to rounding.

## Observed vs expected (eps = 1e-5 unless noted)

| x | `rms_norm` now | golden / `F.rms_norm` |
|---|---|---|
| 0 | **NaN** | 0 |
| 1e-7 | **1** | 3.16e-5 |
| 1e-3 | **1** | 0.3015 |
| -2e-3 | **-1** | -0.5345 |
| 1e-2 | 1 | 0.9535 |
| 1e-6 (eps = 1e-12) | **1** | 0.7071 |
| 1, -5 | 1, -1 | 1, -1 |

## Why the tests do not catch it

The rms_norm tests exercise rank >= 1 tensors; the rank-0 branch has no test with a small or zero input.

Related but different: #49600 (fp32 accuracy of the rank >= 1 kernel).
