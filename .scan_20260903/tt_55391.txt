### 55391 [closed] ttnn.cbrt (FLOAT32) is wrong for every subnormal input, returning 0 or a value up to 6306x low: the magic-constant seed assumes a normal exponent field and SFPMAD flushes the operand
## Summary

`ttnn.cbrt` advertises `FLOAT32` with no range caveat ([`unary_nanobind.cpp#L1684-L1689`](https://github.com/tenstorrent/tt-metal/blob/7b5ae30865b0bf771da32696c9bfcc54ec412a49/ttnn/cpp/ttnn/operations/eltwise/unary/unary_nanobind.cpp#L1684-L1689)), but the fp32 path cannot produce the correct result for any **subnormal** input. The true results are ordinary normal numbers (`cbrt` maps `[1.4e-45, 1.2e-38]` onto `[1.1e-15, 2.3e-13]`), so this is not a range limitation:

```text
x = 1.4013e-45 (smallest subnormal)   torch 1.1190e-15   ttnn: 0, or 1.7744e-19 if subnormals survive the MAD (6306x low)
x = 1.0e-40                           torch 4.6416e-14   ttnn: 0, or 1.2041e-14 (3.9x low)
x = 1.0e-39                           torch 1.0000e-13   ttnn: 0, or 8.1928e-14 (18% low)
```

Which of the two wrong answers appears depends on whether SFPMAD flushes subnormal operands. The comment in [`ckernel_sfpu_sqrt_custom.h#L25`](https://github.com/tenstorrent/tt-metal/blob/7b5ae30865b0bf771da32696c9bfcc54ec412a49/tt_metal/hw/ckernels/wormhole_b0/metal/llk_api/llk_sfpu/ckernel_sfpu_sqrt_custom.h#L25) says it does ("squares to a denormal, SFPMAD flushes it to +0"), in which case `x * y` at the first refinement step is `0`, `d = x * (y*y)` is `0`, and the op returns `±0` for every subnormal input. If a DEST mode preserves them instead, the seed is wrong and the result is the finite-but-wrong value modelled below (29% of subnormals off by more than 1%). Normal inputs are fine (≤ 3 fp32 ULP over `[1e-30, 1e30]`), so this is a domain gap, not a general accuracy problem.

## Root cause

[`ckernel_sfpu_cbrt.h#L38-L47`](https://github.com/tenstorrent/tt-metal/blob/7b5ae30865b0bf771da32696c9bfcc54ec412a49/tt_metal/hw/ckernels/wormhole_b0/metal/llk_api/llk_sfpu/ckernel_sfpu_cbrt.h#L38-L47) (byte-identical on Blackhole) seeds Newton's method with the Moroz magic-constant trick:

```cpp
sfpi::vFloat f = sfpi::convert<sfpi::vFloat>(sfpi::as<sfpi::vSMag>(x), sfpi::RoundMode::Nearest);
f = f * negative_third_256 + magic;                 // i = 0x548c2b4b - i/3, scaled by 1/256
sfpi::vFloat y = sfpi::as<sfpi::vFloat>(sfpi::as<sfpi::vInt>(f) << 8);
```
