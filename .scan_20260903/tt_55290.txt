### 55290 [closed] ttnn.atanh_bw returns NaN for every element whose upstream gradient is exactly zero
**Component / Area:** ttnn eltwise unary backward (composite), `atanh_bw`

**Issue Type:** Bad Outputs

## Summary

`atanh_bw` computes `grad / (1 - x^2)` and then applies

```cpp
grad_a = where(ttnn::eqz(grad), t_nan, grad_a);                       // L972
grad_a = where(logical_and(eqz(grad), eqz(input)), 0.f, grad_a);      // L973-978
```

([unary_backward.cpp#L957-L996](https://github.com/tenstorrent/tt-metal/blob/9fa00fce13cda1538f0130695576408ff5b05665/ttnn/cpp/ttnn/operations/eltwise/unary_backward/unary_backward.cpp#L957-L996)).

The first guard was meant to encode `0 * inf = NaN` at the poles `|x| = 1`, but it has no pole condition. The second guard
rescues only `x == 0`. So every position in the open interval `0 < |x| < 1`, which is the entire finite domain of `atanh`,
returns NaN whenever the upstream gradient is exactly zero. Torch returns 0 there and NaN only at `|x| == 1`.

Zero upstream gradients are routine (attention masks, dropout, padded positions, `where` in the graph). One zero in
`grad` poisons the whole backward pass through this op.

This is a source-level analysis with a host replay; I do not have a card. The `where`/`eqz` chain is exact, so the
device result is NaN where the replay says NaN.

## Observed vs expected

| grad | x | `atanh_bw` now | torch `grad / (1 - x^2)` |
|---|---|---|---|
| 0 | 0.5 | **NaN** | 0 |
| 0 | -0.3 | **NaN** | 0 |
| 0 | 0.9 | **NaN** | 0 |
| 0 | 0.25 | **NaN** | 0 |
| 0 | 0.0 | 0 | 0 |
| 1 | 0.99 | 50.2513 | 50.2513 |
| 0 | 1.0 | NaN | NaN (0 * inf) |

## Why the tests do not catch it

The nightly test
([test_backward_atanh.py](https://github.com/tenstorrent/tt-metal/blob/9fa00fce13cda1538f0130695576408ff5b05665/tests/ttnn/nightly/unit_tests/operations/eltwise/backward/test_backward_atanh.py))
draws `grad` from `uniform(-100, 100)`, so an exact zero never occurs, and the PCC comparison ignores NaN lanes.

This is distinct from #54695 (the final guard rewriting overflowed `+inf` to `-inf` for negative gradients) and #53884
(dispatch count of the guards).
