### Describe the bug

  Environment

  - SGLang version: release/v0.5.18 (with Ascend NPU backports)
  - Hardware: Ascend NPU, CANN 9.0.0 / torch_npu; container quay.io/ascend/sglang:v0.5.18-cann9.0.0-a3
  - Model: Qwen3.8-27B-w8a8 — ModelSlim W8A8_DYNAMIC export of Qwen3.5-27B (48 GatedDeltaNet linear-attention layers with fused in_proj_qkvz/in_proj_ba, 16 full-attention layers, vision tower)

  Reproduction

  sglang serve --model-path /path/to/Qwen3.8-27B-w8a8/ \
      --quantization modelslim --device npu --tp-size 2

  The checkpoint is a proper ModelSlim export: quant_model_description.json marks the fused-GDN shards and the vision tower as W8A8_DYNAMIC, and the weight index contains all 440 weight_scale/weight_offset pairs.

  Actual behavior (three independent failures)

  1. Fused GDN layers silently fall back to unquantized — 48 warnings, then the checkpoint's int8 weights are copied raw into bf16 params (no error, garbage model output):

  Unsupported Linear modelslim scheme: [''] in layer: model.language_model.layers.N.linear_attn.in_proj_qkvz   (all 48 GDN layers)
  Parameter model.layers.N.linear_attn.in_proj_qkvz.weight_scale / weight_offset not found in params_dict

  2. Vision encoder forced unquantized — 162 warnings (27 blocks × attn.qkv_proj / attn.proj / mlp.linear_fc1 × 2 params):

  Parameter visual.blocks.N.attn.qkv_proj.weight_scale / weight_offset not found in params_dict

  3. With 1 and 2 fixed, the server crashes at warmup in the first quantized vision matmul:

  RuntimeError: npu_quant_matmul: ... QuantMatmulKernelNpuOpApi.cpp:297 NPU function error: call aclnnQuantMatmulV5 failed, error code is 161002
  AclNN_Parameter_Error(EZ1001): When x1Scale(pertokenScale), x2Scale(scale) bot
