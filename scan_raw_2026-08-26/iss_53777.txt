# [Bug] DFlash2 spec decode + xgrammar: deterministic "Failed to advance FSM" on json_object grammar (always the same draft token)

## Summary

With a DFlash2 speculative drafter (merged via #52816) and structured-output grammar
(`response_format: {"type": "json_object"}`), the engine repeatedly logs:

```
ERROR ... [backend_xgrammar.py:168] Failed to advance FSM for request <id> for tokens 271. Please file an issue.
```

The failure is **deterministic**: every observed failure is on the same draft token (271 in our
build) under the json_object grammar. The request always recovers (HTTP 200, output is valid JSON),
so this is a draft-vs-grammar interaction bug rather than corruption — but it retries the failing
draft position (we saw up to 7 retry waves for a single request) and spams ERROR-level logs.

## Environment

- vLLM: `0.26.1rc1.dev1045+g3406ec1da` (main, includes merged #52816 "DFlash2: local convolution + candidate selector")
- Model: Qwen3.8-27B-FP8 (hybrid GDN + full-attention architecture, FP8 Marlin)
- Draft: DFlash2 (2B draft model), `--speculative-config '{"method":"dflash","model":"/dflash2-draft","num_speculative_tokens":7}'`
- Hardware: 2× H100 80GB (TP=2), CUDA 13
- Other relevant flags: `--kv-cache-dtype fp8 --enable-prefix-caching --enable-chunked-prefill --async-scheduling --reasoning-parser qwen3` (none believed relevant; happy to bisect if useful)

## Repro

Minimal reproduction — any prompt that makes the model draft token 271 (or whichever token the
FSM rejects) under a json_object grammar. Our verbatim trigger (reproduced 3/3 in a tight loop):

```bash
curl localhost:8000/v1/chat/completions -d '{
  "model": "<served-model-name>",
  "messages": [{"role":"user","content":"Output a JSON config object for a CI job with keys \"name\" (string), \"region\" (string, one of us-east-1 or eu-west-1), \"retries\" (integer 1-3), and \"env\" (object with a KEY=VALUE pair). No prose, JSON only."}],
  "response_format": {"type": "json_object"},
  "max_tokens": 500,
  "temperature": 0
}'
```

Each of the 3 requests produced 2 FSM errors (one per retry at the same position); the model
drafted `\"region\": \"us-east-1\"` in every run, which is where the failure lands. 20 errors total
over ~7h of mixed traffic, always \"for tokens 271\".
